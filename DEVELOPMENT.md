# Developing Nur

Notes for maintainers. For installing and using the layouts, see [README.md](README.md).

## Repository layout

```
Nur.bundle/                     the installable bundle
  Contents/Info.plist           bundle metadata + one KLInfo_<layout name> dict per layout
  Contents/version.plist
  Contents/Resources/
    AM Nur <X>.keylayout        one per layout, maintained by hand
    AM Nur <X>.icns             menu-bar icon, generated by scripts/build-icons.sh
    en.lproj/InfoPlist.strings  English display names
    hy.lproj/InfoPlist.strings  Armenian display names (հյ Նուռ …)
upstream/                       vendored xkeyboard-config symbols/am + COPYING; never edit
  SOURCE.md                     where and when it was fetched, with commit hashes
docs/mapping-tables.md          transcription worksheet: xkb key name → mac keycode → characters
branding/                       SVG sources for icon, logo and banners
scripts/                        validate, install, uninstall, icon build
```

Each `KLInfo_<layout name>` entry in `Info.plist` holds:

| Key | Value |
|---|---|
| `TISInputSourceID` | `am.nur.keyboardlayout.nur.<variant>` (`standard`, `phonetic`, `phonetic-alt`, `eastern`, `western`, `eastern-alt`) |
| `TISIntendedLanguage` | `hy` |
| `TISIconIsTemplate` | `false` |

The bundle id is `am.nur.keyboardlayout.nur`.

| Layout | Upstream variant | Layout id |
|---|---|---|
| AM Nur Standard | `basic` | -21001 |
| AM Nur Phonetic | `phonetic` | -21002 |
| AM Nur Phonetic Alt | `phonetic-alt` | -21003 |
| AM Nur Eastern | `eastern` | -21004 |
| AM Nur Western | `western` | -21005 |
| AM Nur Eastern Alt | `eastern-alt` | -21006 |

Upstream `olpc` and `olpc-phonetic` only add a Linux group-switch option. On macOS they are identical to
Standard and Phonetic Alt, so they aren't shipped.

## The .keylayout files

There is no generator in the repo: the `.keylayout` files are edited by hand (Ukelele can open them if you
prefer a GUI). Keep them in step with `docs/mapping-tables.md`.

- **Header:** XML 1.1 (`<?xml version="1.1" …?>`). XML 1.1 is needed for the control-character references
  (`&#x0008;` etc.) used in the Control map.
- **Ids:** `-21001` … `-21006`. Every layout needs a unique id; a new one takes the next free number.
- **Key maps** (5, selected by `keyMapSelect`):

| Map | Modifiers | Contents |
|---|---|---|
| 0 | none, Option | upstream base level |
| 1 | Shift, Shift+Option | upstream Shift level |
| 2 | Caps Lock, Caps Lock+Option | Shift letter for Armenian letters, base for everything else |
| 3 | Command (any other modifiers) | US QWERTY, so shortcuts work |
| 4 | Control (any other modifiers) | standard control characters |

Upstream has only two levels and no dead keys. Option repeats base/Shift, like AltGr on Linux, which has no
extra level for Armenian.

## macOS rules learned the hard way

Each of these makes macOS silently ignore the layouts or misfile them.

1. **Never write `&#x0000;`.** NUL is illegal in every XML version, and macOS drops the whole file.
   `scripts/validate.sh` checks this.
2. **`CFBundleIdentifier` and every `TISInputSourceID` must contain `keyboardlayout`.**
   `scripts/validate.sh` checks the bundle id; check new input source ids by eye.
3. **Keep the non-Command maps Armenian.** macOS derives a layout's languages from the characters it can
   type outside Command. A Latin Option layer made macOS tag the layouts with ~50 languages instead of
   Armenian.
4. **Design the icon in colour for light and dark.** `TISIconIsTemplate` isn't honoured in the 🌐 switcher,
   so the icon is a colour icon that reads on both backgrounds.
5. **Layouts load at login.** New or changed layouts are only picked up when you log in. For quick tests,
   `TISRegisterInputSource` registers the bundle temporarily without logging out.

## Scripts

| Script | What it does |
|---|---|
| `scripts/validate.sh` | Validates every `.keylayout` against `/System/Library/DTDs/KeyboardLayout.dtd` (on a masked copy: version set to 1.0 and control-character refs replaced, because `xmllint` can't read XML 1.1 control-character refs); fails on NUL refs; `plutil -lint` on the plists and `.strings`; checks layout ids are unique, that each layout has a `KLInfo_<name>` entry and that the bundle id contains `keyboardlayout`. Exit code 0 means all good. |
| `install.sh` | The user installer (`curl … \| sh`). Piped, it downloads the `main` branch tarball from GitHub and installs its `Nur.bundle`; run as a file from a checkout (`sh install.sh`), it installs the checkout's bundle. `--uninstall` removes it. All code is inside `main()` so a partial download never runs. Users fetch it from GitHub Pages (`https://atanesyan-h-pm.github.io/nur-keyboard/install.sh`), which publishes the `main` branch root, so a push to `main` updates it after the Pages build (about a minute). |
| `scripts/install.sh` | Copies `Nur.bundle` to `~/Library/Keyboard Layouts` (per user, no sudo), removes the quarantine flag. Also removes the pre-1.0 `Armenian.bundle`. |
| `scripts/uninstall.sh` | Removes the bundle from `~/Library/Keyboard Layouts`. |
| `scripts/build-icons.sh` | Renders `branding/icon.svg` into an iconset (16–512 px, @1x and @2x), builds an `.icns` and copies it as `<layout name>.icns` next to each `.keylayout`. |
| `scripts/svg2png.swift` | Rasterises an SVG to PNG with macOS's built-in SVG support (no third-party tools). Usage: `swift scripts/svg2png.swift in.svg out.png width [height]`. |

## Changing a key

1. Edit the affected `.keylayout` file(s) **and** `docs/mapping-tables.md` together.
2. Run `scripts/validate.sh`.
3. Run `scripts/install.sh`.
4. Log out and back in (or register the bundle with `TISRegisterInputSource` for a quick test).
5. Check the result in Keyboard Viewer and by typing in TextEdit.

## Testing

Verification is done against what macOS itself does with the installed layouts, not against the XML:

- For each installed Nur input source, read its `kTISPropertyUnicodeKeyLayoutData`.
- Call `UCKeyTranslate` for every key code and modifier combination (base, Shift, Caps Lock, Option,
  Shift+Option, Command).
- Compare the output with `docs/mapping-tables.md`.

Last run: 6 layouts, 1713 key/modifier pairs including Option and Command, 0 mismatches.
There is no test script in the repo yet.

### Manual release checks

After installing and logging back in:

- [ ] All six layouts appear in Input Sources under Armenian.
- [ ] Keyboard Viewer shows the expected characters for each layout (base, Shift, Caps Lock, Option).
- [ ] A test sentence types correctly in TextEdit with each layout.
- [ ] Cmd+C / Cmd+V / Cmd+Z / Cmd+Q work with every layout.

## Updating from upstream

1. Re-download `symbols/am` and `COPYING` from
   [xkeyboard-config](https://gitlab.freedesktop.org/xkeyboard-config/xkeyboard-config) into
   `upstream/symbols-am` and `upstream/COPYING`.
2. Update the hashes and date in `upstream/SOURCE.md`.
3. Diff against the previous version (`git diff upstream/`).
4. Apply the changes by hand to `docs/mapping-tables.md` and the `.keylayout` files, then follow
   [Changing a key](#changing-a-key).

## Adding a layout

1. Create `Nur.bundle/Contents/Resources/AM Nur <X>.keylayout` with a new unique id and `name="AM Nur <X>"`.
2. Add a `KLInfo_AM Nur <X>` dict to `Info.plist` (`TISInputSourceID` `am.nur.keyboardlayout.nur.<x>`,
   `TISIntendedLanguage` `hy`, `TISIconIsTemplate` false).
3. Add the English and Armenian names to `en.lproj/InfoPlist.strings` and `hy.lproj/InfoPlist.strings`.
4. Run `scripts/build-icons.sh` to create its `.icns`.
5. Add its table to `docs/mapping-tables.md`, run `scripts/validate.sh`, and test as above.

## Branding

| File | Use |
|---|---|
| `branding/icon.svg` | input-source icon (menu bar and 🌐 switcher) |
| `branding/logo.svg` | logo |
| `branding/banner-light.svg`, `branding/banner-dark.svg` | README banner for light and dark mode |

The pomegranate is drawn on a 16×16 knot grid: each 1×1 square is one rug knot, the way a rug is woven.
Keep shapes on whole-unit coordinates (`shape-rendering="crispEdges"`) so the icon stays sharp at 16 px.

| Colour | Hex | Used for |
|---|---|---|
| Madder red | `#A3232F` | pomegranate body |
| Saffron | `#D49A2E` | crown and seeds |
| Indigo | `#1E2747` | banners (light banner artwork, dark banner background) |
| Cream | `#F4EAD5` | outline |
| Walnut | `#5B3A29` | banner accents |

After editing `branding/icon.svg`, run `scripts/build-icons.sh`, then `scripts/validate.sh`, reinstall and
log out and back in to see the new icon.

### User-guide pictures

`docs/images/step-*.svg` are drawn (not captured) illustrations of the install steps: Terminal, Log Out,
Keyboard settings, the + list and the input menu. They use simplified light-mode macOS UI, red numbered
callouts in the brand colours, and embed the paths from `branding/icon.svg`. Edit them as SVG; if the
installer output, layout names or macOS menus change, update them to match.
