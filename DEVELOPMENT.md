# Developing Nur

Notes for maintainers. For installing and using the layouts, see [README.md](README.md).

## Repository layout

```
Nur.bundle/                     the installable bundle
  Contents/Info.plist           bundle metadata + one KLInfo_<layout name> dict per layout
  Contents/version.plist
  Contents/Resources/
    AM Nur <X>.keylayout        one per layout, maintained by hand
    AM Nur <X>.icns             menu-bar icon, generated by scripts/build-icons.sh from branding/icons/
    en.lproj/InfoPlist.strings  English display names
    hy.lproj/InfoPlist.strings  Armenian display names (հյ Նուռ …)
upstream/                       vendored xkeyboard-config symbols/am + COPYING; never edit
  SOURCE.md                     where and when it was fetched, with commit hashes
docs/mapping-tables.md          transcription worksheet: xkb key name → mac keycode → characters
branding/                       SVG sources: per-layout icons (branding/icons/), logo, banners
scripts/                        validate, layout test, install/uninstall wrappers, icon build
install.sh                      the user installer (curl … | sh); scripts/install.sh wraps it
dist/                           release build output (git-ignored): Nur.bundle.zip
```

Each `KLInfo_<layout name>` entry in `Info.plist` holds:

| Key | Value |
|---|---|
| `TISInputSourceID` | `am.nur.keyboardlayout.nur.<variant>` (`standard`, `phonetic`, `phonetic-alt`, `eastern`, `western`, `eastern-alt`) |
| `TISIntendedLanguage` | `hy` |
| `TISIconIsTemplate` | `false` |

The bundle id is `am.nur.keyboardlayout.nur`.

| Layout | Upstream variant | Layout id |
|---|---|---|
| AM Nur Standard | `basic` | -21001 |
| AM Nur Phonetic | `phonetic` | -21002 |
| AM Nur Phonetic Alt | `phonetic-alt` | -21003 |
| AM Nur Eastern | `eastern` | -21004 |
| AM Nur Western | `western` | -21005 |
| AM Nur Eastern Alt | `eastern-alt` | -21006 |

Upstream `olpc` and `olpc-phonetic` only add a Linux group-switch option. On macOS they are identical to
Standard and Phonetic Alt, so they aren't shipped.

## The .keylayout files

There is no generator in the repo: the `.keylayout` files are edited by hand (Ukelele can open them if you
prefer a GUI). Keep them in step with `docs/mapping-tables.md`.

- **Header:** XML 1.1 (`<?xml version="1.1" …?>`). XML 1.1 is needed for the control-character references
  (`&#x0008;` etc.) used in the Control map.
- **Ids:** `-21001` … `-21006`. Every layout needs a unique id; a new one takes the next free number.
- **Key maps** (5, selected by `keyMapSelect`):

| Map | Modifiers | Contents |
|---|---|---|
| 0 | none, Option | upstream base level |
| 1 | Shift, Shift+Option | upstream Shift level |
| 2 | Caps Lock, Caps Lock+Option | Shift letter for Armenian letters, base for everything else |
| 3 | Command (any other modifiers) | US QWERTY, so shortcuts work |
| 4 | Control (any other modifiers) | standard control characters |

Upstream has only two levels and no dead keys. Option repeats base/Shift, like AltGr on Linux, which has no
extra level for Armenian.

## macOS rules learned the hard way

Each of these makes macOS silently ignore the layouts or misfile them.

1. **Never write `&#x0000;`.** NUL is illegal in every XML version, and macOS drops the whole file.
   `scripts/validate.sh` checks this.
2. **`CFBundleIdentifier` and every `TISInputSourceID` must contain `keyboardlayout`.**
   `scripts/validate.sh` checks the bundle id and every `KLInfo_<name>.TISInputSourceID`.
3. **Keep the non-Command maps Armenian.** macOS derives a layout's languages from the characters it can
   type outside Command. A Latin Option layer made macOS tag the layouts with ~50 languages instead of
   Armenian.
4. **Design the icon in colour for light and dark.** `TISIconIsTemplate` isn't honoured in the 🌐 switcher,
   so the icon is a colour icon that reads on both backgrounds.
5. **Layouts load at login.** New or changed layouts are only picked up when you log in. For quick tests,
   `TISRegisterInputSource` registers the bundle temporarily without logging out.

## Scripts

Only built-in macOS tools are used (`sh`, `bash`, `swift`/`swiftc`, `xmllint`, `plutil`, `iconutil`,
`shasum`, `xattr`, `curl`, `tar`). `install.sh` is POSIX `#!/bin/sh` (`set -eu`); everything in `scripts/` is
`#!/bin/bash` with `set -euo pipefail` (except `validate.sh`, see below).

| Script | What it does |
|---|---|
| `scripts/validate.sh` | Static checks. Validates every `.keylayout` against `/System/Library/DTDs/KeyboardLayout.dtd` on a masked copy: the version is set to 1.0 and XML 1.1 control-character references are replaced, because `xmllint` can't read them. The masking covers hex in any case and length (`&#x8;`, `&#x001B;`, `&#x007f;`) and decimal (`&#8;`, `&#127;`). Also: fails on NUL references (`&#x0;`, `&#0;` …); checks every layout has its `.icns` and a `branding/icons/<variant>.svg`; checks each layout has a `KLInfo_<name>` entry whose `TISInputSourceID` contains `keyboardlayout`; `plutil -lint` on the plists and `.strings`; unique layout ids; bundle id contains `keyboardlayout`. Uses `set -uo pipefail` (no `-e`) so every check runs and reports; exit code 0 means all good. |
| `scripts/test-layouts.swift` | Behavioural test through macOS itself; see [Testing](#testing). |
| `install.sh` | The user installer (`curl … \| sh`), served from GitHub Pages. Options: none (install), `--uninstall`, `--clear-cache`, `--help`; unknown or combined options exit 2. **Install:** piped, it downloads the release pinned in `VERSION` (a tag, not `main`) to a temp file, checks it against `EXPECTED_SHA256` with `shasum -a 256 -c` (warns if that's empty), extracts it and installs its `Nur.bundle`; run as a file named `install.sh` from a checkout (`sh install.sh`, `./install.sh`, via a symlink) it installs the checkout's bundle instead — never when piped, since `$0` is then the shell, so a stray `sh` file can't trick it. On an upgrade it lists enabled Nur entries (by id `-2100N` or a name containing `Nur`) that have no `.keylayout` in the new bundle — ghosts left by renames — and tells the user to remove and re-add them. Names are decoded for display by converting the `defaults read` output with `plutil -convert xml1` (it prints non-ASCII as `\Uxxxx`); if that fails it falls back to the raw text. **Uninstall:** if Nur layouts are still enabled (`defaults read com.apple.HIToolbox AppleEnabledInputSources`), it explains the System Settings step and waits for Return on `/dev/tty` (`read … </dev/tty \|\| true`, so Ctrl-D can't abort it; skipped without a terminal), then removes the bundle. **Cache:** install, uninstall and `--clear-cache` delete `$(getconf DARWIN_USER_CACHE_DIR)/com.apple.IntlDataCache.le*` (never fatal); macOS rebuilds it at login. All code is inside `main()` so a partial download never runs. |
| `scripts/install.sh` | Thin wrapper: `exec sh ../install.sh`, which installs the checkout's bundle. |
| `scripts/uninstall.sh` | Thin wrapper: `exec sh ../install.sh --uninstall`. |
| `scripts/build-icons.sh` | Compiles `svg2png.swift` once with `swiftc -O`, then for each `.keylayout` reads its `TISInputSourceID`, renders `branding/icons/<suffix>.svg` into an iconset (16–512 px, @1x and @2x) and writes `<layout name>.icns` next to it. Fails if a layout has no SVG. |
| `scripts/package-release.sh` | Removes any previous `dist/Nur.bundle.zip` first, runs `validate.sh`, then zips a clean copy of `Nur.bundle` (no `.DS_Store`, no extended attributes, no `__MACOSX`) to `dist/Nur.bundle.zip` for the GitHub Release, self-checks the archive (all `.keylayout` and `.icns` present) and prints its size and SHA-256. If any step fails, it deletes the zip, so `dist/` never holds an archive that doesn't match the current tree. |
| `scripts/svg2png.swift` | Rasterises an SVG to PNG with macOS's built-in SVG support, nearest-neighbour scaling for the pixel icon. Usage: `swift scripts/svg2png.swift in.svg out.png width [height]`. Any bad argument, unreadable image, missing or read-only output folder, or write error prints to stderr and exits 1; it never writes a blank PNG with exit code 0. |

## Releasing

The live installer downloads a tagged release, and the Finder install downloads the `Nur.bundle.zip` attached
to the latest GitHub Release, so a push to `main` alone doesn't change what users install.

1. Bump `CFBundleShortVersionString` / `CFBundleVersion` in `Nur.bundle/Contents/Info.plist` and
   `version.plist`, then make sure `scripts/validate.sh` and
   `swift scripts/test-layouts.swift --bundle Nur.bundle` pass. Commit.
2. Tag and push the tag only: `git tag -a vX.Y.Z -m "…" && git push origin vX.Y.Z`.
3. Build the Finder download and publish the release (the asset must be named exactly `Nur.bundle.zip`,
   because the README links to `releases/latest/download/Nur.bundle.zip`):
   `scripts/package-release.sh && gh release create vX.Y.Z dist/Nur.bundle.zip --title "Nur X.Y.Z" --notes "…"`
   (or create the release in the GitHub web UI and upload `dist/Nur.bundle.zip`).
4. Compute the tag tarball checksum:
   `curl -fsSL https://github.com/atanesyan-h-pm/nur-keyboard/archive/refs/tags/vX.Y.Z.tar.gz | shasum -a 256`
5. Set `VERSION` and `EXPECTED_SHA256` in `install.sh` to the tag and that checksum, commit and push `main`.
   GitHub Pages republishes `install.sh` in about a minute.
6. Test both live paths: `curl -fsSL https://atanesyan-h-pm.github.io/nur-keyboard/install.sh | sh`, and
   `curl -fsSL -L https://github.com/atanesyan-h-pm/nur-keyboard/releases/latest/download/Nur.bundle.zip`.

`install.sh` must never point at a tag that doesn't exist on GitHub yet: the download would fail for every
user. GitHub generates tag tarballs on the fly; they have been stable in practice, but if the checksum ever
stops matching for an unchanged tag, re-check it and update `EXPECTED_SHA256`.

## Changing a key

1. Edit the affected `.keylayout` file(s) **and** `docs/mapping-tables.md` together.
2. Run `scripts/validate.sh`.
3. Run `swift scripts/test-layouts.swift --bundle Nur.bundle` (no logout needed).
4. Run `scripts/install.sh`, log out and back in, and check the result in Keyboard Viewer and by typing in
   TextEdit.

## Testing

`scripts/test-layouts.swift` checks what macOS itself types with each layout, not what the XML says:

```bash
swift scripts/test-layouts.swift                      # the installed bundle, as macOS has it loaded
swift scripts/test-layouts.swift --bundle Nur.bundle  # the checkout's files, no install or logout needed
```

For every Nur input source it reads `kTISPropertyUnicodeKeyLayoutData` and calls `UCKeyTranslate` for every
key in `docs/mapping-tables.md` with base, Shift, Caps Lock, Option, Shift+Option and Command. The
expected values come from the tables:

- base and Shift are the cell's two characters;
- Caps Lock gives the Shift character for letters (when it's the base letter's capital), base otherwise;
- Option and Shift+Option equal base and Shift;
- Command is the US QWERTY character.

Every mismatch is printed with layout, xkb key, key code, modifier, and expected vs. actual. The exit status
is 1 on any mismatch or a missing layout. Current result: 6 layouts, 1713 key/modifier pairs, 0 mismatches.

Without `--bundle` it tests the installed `~/Library/Keyboard Layouts/Nur.bundle` (or the checkout's, if
nothing is installed), and warns if the installed copy differs from the checkout.

With `--bundle`, the files are tested through a temporary copy,
`~/Library/Keyboard Layouts/NurTest-<random>.bundle`, registered with `TISRegisterInputSource`. The copy gets
a unique bundle id, unique `TISInputSourceID`s and unique numeric layout ids. macOS needs all three before it
compiles the files fresh:

- It caches input sources by id: a changed bundle registered under the installed ids silently returns the
  old layouts.
- It rejects layouts whose numeric id is already loaded.
- It only registers bundles inside a Keyboard Layouts folder.

The copy is deleted on exit and on Ctrl-C, and leftovers from a killed run are removed at the next start.
macOS remembers the temporary sources until you log out; they are never enabled.

### Manual release checks

After installing and logging back in:

- [ ] All six layouts appear in Input Sources under Armenian.
- [ ] Keyboard Viewer shows the expected characters for each layout (base, Shift, Caps Lock, Option).
- [ ] A test sentence types correctly in TextEdit with each layout.
- [ ] Cmd+C / Cmd+V / Cmd+Z / Cmd+Q work with every layout.
- [ ] Each layout shows its own icon in the menu bar and the 🌐 switcher, in light and dark mode.
- [ ] Finder install from the release's `Nur.bundle.zip` (downloaded with Safari, so it's quarantined) loads after
      logging back in.

## Updating from upstream

1. Re-download `symbols/am` and `COPYING` from
   [xkeyboard-config](https://gitlab.freedesktop.org/xkeyboard-config/xkeyboard-config) into
   `upstream/symbols-am` and `upstream/COPYING`.
2. Update the hashes and date in `upstream/SOURCE.md`.
3. Diff against the previous version (`git diff upstream/`).
4. Apply the changes by hand to `docs/mapping-tables.md` and the `.keylayout` files, then follow
   [Changing a key](#changing-a-key).

## Adding a layout

1. Create `Nur.bundle/Contents/Resources/AM Nur <X>.keylayout` with a new unique id and `name="AM Nur <X>"`.
2. Add a `KLInfo_AM Nur <X>` dict to `Info.plist` (`TISInputSourceID` `am.nur.keyboardlayout.nur.<x>`,
   `TISIntendedLanguage` `hy`, `TISIconIsTemplate` false).
3. Add the English and Armenian names to `en.lproj/InfoPlist.strings` and `hy.lproj/InfoPlist.strings`.
4. Add its icon as `branding/icons/<x>.svg` (the `TISInputSourceID` suffix; see [Layout icons](#layout-icons)) and run
   `scripts/build-icons.sh` to create its `.icns`.
5. Add its table to `docs/mapping-tables.md`, run `scripts/validate.sh`, and test as above.

## Branding

| File | Use |
|---|---|
| `branding/icons/<variant>.svg` | per-layout input-source icons (menu bar and 🌐 switcher); see below |
| `branding/icon.svg` | the plain pomegranate (brand/logo; identical to `icons/standard.svg`) |
| `branding/logo.svg` | logo |
| `branding/banner-light.svg`, `branding/banner-dark.svg` | README banner for light and dark mode |

The pomegranate is drawn on a 16×16 knot grid: each 1×1 square is one rug knot, the way a rug is woven.
Keep shapes on whole-unit coordinates (`shape-rendering="crispEdges"`) so the icon stays sharp at 16 px.

| Colour | Hex | Used for |
|---|---|---|
| Madder red | `#A3232F` | pomegranate body |
| Saffron | `#D49A2E` | crown and seeds |
| Indigo | `#1E2747` | banners (light banner artwork, dark banner background) |
| Cream | `#F4EAD5` | outline |
| Walnut | `#5B3A29` | banner accents |

### Layout icons

Every layout has its own icon so people can tell from the menu bar which one is on. Only the centre seed
medallion (rows 8–12, columns 5–10 of the 16×16 grid) changes; crown, body, outline and the cream seed ring
are the same everywhere, so the pomegranate stays recognisable.

| Layout | File | Seeds |
|---|---|---|
| Standard | `icons/standard.svg` | saffron diamond (the classic icon) |
| Phonetic | `icons/phonetic.svg` | indigo diamond |
| Phonetic Alt | `icons/phonetic-alt.svg` | indigo stripe through the eye |
| Eastern | `icons/eastern.svg` | madder diamond |
| Eastern Alt | `icons/eastern-alt.svg` | madder stripe through the eye |
| Western | `icons/western.svg` | cream (the eye is solid cream) |

Rules: **seed colour = layout family, stripe = Alt.** The colours are separated by brightness (indigo, madder,
saffron, cream), not just hue; walnut isn't used because at 16 px it can't be told from madder. The Alt stripe
runs through the cream ring and splits the eye in two: a 4-knot bar inside the ring was too subtle at 16 px
between Eastern and Eastern Alt. Check new icons at true 16 px on light (`#ECECEC`) and dark (`#2B2B2D`).
`TISIconIsTemplate` stays `false`.

After editing an icon, run `scripts/build-icons.sh`, then `scripts/validate.sh`, reinstall and
log out and back in to see the new icon.

### User-guide pictures

`docs/images/step-*.svg` are drawn (not captured) illustrations of the install steps: Terminal, Log Out,
Keyboard settings, the + list and the input menu. They use simplified light-mode macOS UI, red numbered
callouts in the brand colours, and embed the paths from `branding/icon.svg`. Edit them as SVG; if the
installer output, layout names or macOS menus change, update them to match.
